## Root causes found

1. Most Converter Hub pages contain a static `.converter-language-link` English/Chinese anchor in the header while also loading the Non-AI runtime, which mounts a second `<select>`.
2. Legacy finance pages contain `.lang-selector` / `.lang-dropdown` / `.lang-btn` markup. The runtime only selected the first `.lang-selector`, so pages with multiple legacy hosts could retain additional controls.
3. AI pages use independent interface-language controls and, in some tools, additional functional language controls. Those controls are not interchangeable with the Non-AI runtime and require a separate catalog audit.
4. The Non-AI runtime selected the document's default `lang` attribute before `navigator.language`, so a source page marked `zh-TW` could override the requested fallback order.
